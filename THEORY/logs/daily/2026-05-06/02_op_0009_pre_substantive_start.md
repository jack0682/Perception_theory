## §1. Mission Statement

The central tension in multi-formation SCC theory:

> **I9 (canonical ~line 846):** K-field architecture introduces K *labeled* coupled fields $u^{(1)}, \ldots, u^{(K_{\mathrm{field}})} \in \Sigma^K_M = \Sigma_{m_1} \times \cdots \times \Sigma_{m_K}$ with inter-field repulsion and simplex participation constraint. This *guarantees K > 1 by construction*.

> **Commitment 1 (canonical.md ~line 757):** The primitive ontological entity is $u_t : X_t \to [0,1]$, *not a class label, not an instance ID*.

The *prima facie* conflict: K-field indices $j \in \{1, \ldots, K_{\mathrm{field}}\}$ act as *instance IDs*. The architecture presupposes K individuated objects, contradicting the pre-objective promise.

**Resolution path (Tool A2 from `mathematical_scaffolding_4tools.md` §3, now made explicit):**

The correct ontological entity for multi-formation SCC is the *unordered K-field configuration class* $[\mathbf{u}] \in \widetilde{\widetilde\Sigma}^K_M := \Sigma^K_M / S_{K_{\mathrm{field}}}$, where $S_{K_{\mathrm{field}}}$ is the symmetric group permuting slot indices. The ordered K-field $\mathbf{u} = (u^{(1)}, \ldots, u^{(K)})$ is a *modeling-layer analytical lift* of $[\mathbf{u}]$, not an ontologically primary object.

**Why this matters:** In $\widetilde{\widetilde\Sigma}^K_M$, there are no instance IDs — only a collection of cohesion fields as an unordered multi-set. Commitment 1's *"not a class label, not an instance ID"* is automatically satisfied at the class level. K-field architecture provides an efficient computational handle via ordered representatives, but the ontological commitment is at the class level.
